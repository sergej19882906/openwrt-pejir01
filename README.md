# OpenWrt 25.12 для Perenio Elegance (PEJIR01)

Порт **OpenWrt v25.12.6** (ядро 6.12.112) на мультфункциональный IoT-роутер
**Perenio Elegance / A1 Elegance (PEJIR01)** — MediaTek MT7621A, 256 МБ RAM,
128 МБ NAND, Wi-Fi 2.4+5 ГГц, гигабитные порты, LTE-модем, Zigbee.

> ⚠️ Порт сообщества. Гарантий нет: сначала бэкап, потом прошивка.
> Разделение прошивок A1/Perenio больше не требуется — один образ на оба бренда.
> **Калибровка Wi-Fi и MAC не затрагиваются** (раздел `factory`/`idata` — read-only).

> 🔖 **Актуальный релиз — `25.12.6-pejir01.53`**: исправлен запуск init-скриптов — без этого `pejir-sync`, запись `smsd.conf` и определение AT-порта не работали **с момента появления патча 0018**. Подробности — [docs/CHANGELOG.md](docs/CHANGELOG.md).

**Релиз `25.12.6-pejir01.53`** (патч 0085): init-скрипты теперь
**реально запускаются при загрузке**. До этого они молчали: в OpenWrt
функция `start_service()` вызывается только если скрипт объявил
`USE_PROCD=1`, а наши четыре скрипта (`40-pejir-sms`, `41-pejir-modem`,
`47-pejir-lte`, `41-pejir-sync`) его не объявляли — `/etc/rc.common`
выполнял свой `start() { return 0; }` и `start_service()` не вызывался
**никогда**. Механизм не работал с момента появления в патче 0018, и
это объясняет, почему `pejir-sync` не восстанавливал протухшие копии
файлов пакетов, а `smsd.conf` и AT-порт писались только вручную.


**Релиз `25.12.6-pejir01.52`** (патчи 0083–0084, run 45349537052,
релиз 456485311): sysupgrade 17 562 168 Б
(sha256 `0066b278eeb9b916b7e006fa47a01f0da30391f4ee0a8f5e25fe23eacad0b798`),
factory 23 855 104 Б, initramfs 16 888 742 Б, rootfs 14 086 144 Б.
Исправляет разбор
`/proc/mounts`, из-за которого в `.51` не работали оба новых механизма
чистки:

- Поиск `upperdir=` шёл по **отдельным полям** строки `/proc/mounts`, а
  опции mount'а - это **одно поле с запятыми**
  (`rw,lowerdir=...,upperdir=...`). Поэтому `upperdir=` не находился
  **никогда**, и `find_upper_dir()` падала в захардкоженные пути — на
  верхний слой определялся по захардкоженным путям, а не по данным
  устройства. Из-за этого `pejir-sync` не
  восстанавливал протухшие копии файлов пакетов, а `pejir-ovl-purge`
  вычищал не то самое перед `sysupgrade`.
- Теперь `upperdir=` ищется по всей строке, и сначала берётся **корневой
  mount** (mountpoint = `/`, fstype = `overlay`), а не первый подходящий.
- Режим `pejir-ovl-purge --print-upper` показывает найденный верхний
  слой — для диагностики на устройстве.


**Релиз `25.12.6-pejir01.51`** (патч 0083) — **не публиковался**: в нём
найден дефект разбора `/proc/mounts` (см. `.52` ниже), поэтому сборка была
остановлена. Ставить нечего, переходите сразу на `.52`. Он чинит
**корневые причины** двух дефектов, которые ломали устройство даже после
прошивки `.46`, `.48` и `.50`:

- **Кодировка SMS больше не зависит от AT-ответа.** Раньше `write_conf()`
  вызывался только после успешной `detect_at_port()`, а на живом устройстве
  модем не отвечает на AT, пока активен LTE-вызов («AT port is blocked
  while the LTE data call is active»). Из-за этого `/etc/smsd.conf`
  оставался без глобальных опций `alphabet = utf`, `outgoing_utf8 = yes`,
  `incoming_utf8 = yes`, smsd читал `default_alphabet = ISO-8859-15`, а
  кириллица выбрасывалась («Cannot convert N character to GSM»). Теперь
  опции применяются сразу при старте сервиса.
- **Протухшие копии файлов пакетов не переживают прошивку.** Верхний слой
  overlay при `sysupgrade` не пересоздаётся, а бэкап `-c` собирает **все**
  файлы из `/overlay/upper/etc` — значит старая копия
  `/etc/init.d/40-pejir-sms` возвращалась на каждой прошивке и перекрывала
  свежие файлы образа (старый скрипт, ACL без гранта `exec`, `pejir-ussd`
  без декодера UCS2, `pejir-led` со старым `pejir-led off`). Новый helper
  `pejir-ovl-purge` чистит верхний слой **до** `sysupgrade`.
- `pejir-sync` теперь берёт верхний слой именно у корневого mount'а
  (в extroot-системе mount'ов с `fstype overlay` несколько) и пишет в
  syslog с тегом `pejir-sync`.

Обновление обычным способом (кнопка «Firmware update (PEJIR01)» в LuCI)
теперь само чистит верхний слой перед прошивкой — ручная очистка не нужна.

### Если устройство уже на `.52`

Чистить верхний слой вручную **не нужно**: в образе `.52` есть helper
`pejir-ovl-purge`, и `pejir-ota` вызывает его **до** `sysupgrade`.
Просто прошейте `.53` обычной кнопкой в LuCI.

Что изменится при первой загрузке: скрипты `41-pejir-sync`,
`40-pejir-sms`, `41-pejir-modem` и `47-pejir-lte` наконец **начнут
работать**. Загрузка может занять на минуту дольше обычного - скрипты
ждут появления модема в USB (`MODEM_WAIT`), а если модем не ответил на
AT, поиск продолжается в фоне. Проверить, что всё отработало, можно
скриптом:

```sh
wget -O /tmp/c53.sh "https://github.com/sergej19882906/openwrt-pejir01/releases/download/v25.12.6-pejir01.53/check_rel53.sh" && sh /tmp/c53.sh
```



### Если устройство уже на `.50`

В образе `.50` очистки верхнего слоя ещё нет (helper `pejir-ovl-purge`
появился в `.52`), поэтому **до** прошивки `.52` верхний слой надо
почистить один раз вручную — иначе протухшие копии файлов пакетов уедут
в бэкап `sysupgrade -c` и опять перекроют свежие файлы образа:

```sh
wget -O /tmp/sync52.sh "https://github.com/sergej19882906/openwrt-pejir01/releases/download/v25.12.6-pejir01.50/sync52.sh" && sh /tmp/sync52.sh
```

Скрипт чистит верхний слой от протухших копий, восстанавливает файлы
пакетов из `/rom`, пишет опции кодировки в `/etc/smsd.conf` и
перезапускает службу SMS. После этого прошивайте `.52` обычной кнопкой
в LuCI — дальше чистка пойдёт автоматически.


**Релиз `25.12.6-pejir01.50`** (патчи 0081–0082, run 45260112368):
sysupgrade 17 562 168 Б
(sha256 `dd33ba445f917f3007c32e23a58e88fc2ddcac89caf034a542dff6677a8d0f99`),
factory 23 855 104 Б, initramfs 16 881 943 Б, rootfs 14 082 048 Б.
 **USSD теперь читаемый** —
ответ оператора приходил «кучей непонятных символов». Причина была двойная:
ответ модема читался командной подстановкой `$(...)`, которая **теряет
NUL-байты**, а ответ в UCS2 — это UTF-16BE, где младший байт у
неASCII-символов равен нулю; плюс байты выводились как есть, без учёта
схемы кодирования из поля `dcs`. Теперь ответ читается во файл (NUL-safe),
разбирается по схеме DCS так же, как в стоковом `dcs.sh`, и UCS2
переводится в UTF-8. И **индикация LED больше не «слетает»** после
перезагрузки: `stop_service()` вызывал `pejir-led off`, а эта команда
не только гасит железо, но и записывает в `/etc/pejir/led.conf` режим
`manual 0` для всех семи индикаторов. Добавлена команда `blank` —
гасит лампы, не трогая настройки.

В `.34` исправлено главное, что оставалось: **LTE поднимался, но трафика
не было**. Модем GM510 отвечает на AT только с символом конца строки CR: на
`AT\n` (только LF) он **не отвечает вовсе** — 6 минут проб дали тишину, — а
`mdm-at`, который шлёт `AT\r`, порт находил. Из-за этого `47-pejir-lte` не
находил порт, не ставил APN и не создавал PDP-контекст. Теперь проба
трёхступенчатая (`AT\r` → `AT+CSQ\r` → `AT+CSQ\n`), а `smsd` на время
AT-обмена отпускает порт — иначе он забирал ответы модема себе (патч 0059).

поднимался без ручного вмешательства), а поиск порта **продолжается в
фоне**, если модем ещё не готов. В образ добавлен **ModemManager** с
страницей LuCI «Модем» (в `.33` удалён — см. выше). В маркере версии
`/usr/lib/pejir/version` теперь стоит реальный номер релиза.

В `.28` исправлены вещи, которые были сломаны и раньше, но мешали
пользоваться устройством: **страницы порта больше не отдают «Permission
denied»** (в ACL LuCI 25.12 не хватало раздела `file` — подробности в
`docs/CHANGELOG.md`), **smsd запускается** с правильным портом модема
(`ttyUSB2`), **добавлен ECM data call** `AT+ZECMCALL=1`, а `mcud` при
неудачном старте пишет причину в журнал, а не выходит молча.

**Язык интерфейса** — русский по умолчанию, английский переключается
на **System → Administration → Language** (там же `auto`). Переводы
есть и у штатных страниц LuCI, и у страниц порта: их исходные строки
английские, русские — в `*.ru.lmo`.

**Overlay можно перенести на USB-флешку** (extroot): `pejir-extroot`
покажет состояние, `pejir-extroot setup` подготовит флешку (ext4) и
запишет конфигурацию, после `reboot` настройки хранятся на флешке, а не
в NAND.

В предыдущем релизе `.26` было главное — **само обновление прошивки по
воздуху**: rootfs пишется в существующий UBI-том, `rootfs_data` (overlay с
настройками) не стирается.
В `.26` из образа убран `sing-box` (50 МБ) — rootfs стал 14 МБ и влезает в
существующий UBI-том, поэтому обновление больше не стирает настройки
(Wi-Fi, LTE, пароли). Ставится отдельно: `apk add sing-box`.
В `.24` DTB приведён к реальному железу: `kernel0` больше не `read-only`
(иначе ядро не записывалось при обновлении), кнопка на плане — это WPS,
а не reset; `i2c` и третий UART выключены, как в заводском DTB.
Полный список изменений — [docs/CHANGELOG.md](docs/CHANGELOG.md).
Обновляться можно сразу с `.12` на `.25`.

### Как появляется релиз

Релиз создаёт workflow `Build` — но только при пуше тега вида `v*`:

1. тег `v<версия>` указывает на нужный коммит `main`;
2. workflow собирает образы и прикрепляет их к релизу с этим тегом
   (`factory.bin`, `sysupgrade.bin`, `initramfs-kernel.bin`, `sha256sums`).

Тег можно поставить через веб-интерфейс GitHub: **Releases → Create new release →
«Create new tag on: main»**. Сборка занимает около часа, кэш сборки переиспользуется.

## Как собрать

```sh
git clone https://github.com/sergej19882906/openwrt-pejir01.git
cd openwrt-pejir01 && bash build.sh
```

Вендорные бинарники (`mcu`, `mcud`, `stm32flash`, `idata_*`) **не входят в репозиторий** —
build.sh берёт их из официальной прошивки 9.0.4 (публичный S3 Perenio),
при недоступности — из zip-ассета релиза, а если нет и его — из локального
файла прошивки: положите `pejir-9.0.4.swu` рядом с `build.sh` или укажите
путь в `STOCK_FW=... ./build.sh`. Детали: [docs/BUILD.md](docs/BUILD.md).

Серия патчей: `patches/0001..0030` (`git am` на чистый v25.12.6).

### Сборка на GitHub

В репозитории есть workflow [`.github/workflows/build.yml`](.github/workflows/build.yml):
он собирает образ на `ubuntu-latest`, **проверяет содержимое собранного rootfs**
(что OTA-модуль, `luci-app-perenio`, `pejir-idata`, вендорные `mcu`/`mcud` и
symlink'и `libubox`/`libubus` реально попали в образ — иначе сборка падает)
и отдаёт образы артефактом. При пуше тега `v*` образы дополнительно
прикрепляются к Release.

```sh
# запустить вручную
gh workflow run build.yml
# или поставить тег — релиз соберётся сам
git tag v25.12.6-pejir01.7 && git push origin v25.12.6-pejir01.7
```

Сборка занимает несколько часов (лимит GitHub-hosted — 6 ч), но повторные
запуски быстрые: `dl/`, `build_dir/` и `staging_dir/` кэшируются.

## Как прошить

Кратко (полностью — [docs/FLASH.md](docs/FLASH.md)):

1. **Бэкап** NAND-разделов со стока (SSH → `dd` → SCP) — страховка от ручных ошибок.
2. Зажать Reset, подать питание → веб-интерфейс U-Boot на `192.168.1.1`
   (ПК со статикой `192.168.1.2/24`).
3. Прошить `...squashfs-factory.bin`.

После прошивки: `192.168.1.1`, LuCI (тема Argon; остальные — в выпадающем списке).
Пароль root — из стокового `admin_pass` (миграция idata); на «чистом» железе — пустой, задайте сразу.

Калибровка Wi-Fi и MAC не затрагиваются: разделы `factory`/`idata` — read-only,
прошивается только kernel+ubi.

> ⚠️ **При обновлении через LuCI всегда ставьте галочку «Сохранить настройки
> и текущую конфигурацию».** Без неё overlay очищается, и теряются Wi-Fi,
> WAN/LTE и — главное — fstab extroot: флешка перестаёт монтироваться, а
> путь к `/overlay` приходится создавать заново. Настройки стоковой прошивки
> (SSID, пароли, MAC) восстанавливаются из раздела `idata` автоматически,
> но всё, что настроено руками, — нет.
