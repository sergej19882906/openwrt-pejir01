# STM32: батарея, питание, звук

Источник: разбор заводской прошивки 9.0.4 (скрипты `stminfo.sh`, `events/*`,
`efm_ota`) + данные 4PDA #794/#816. Всё ниже доступно в нашем образе сразу —
демон `mcud` стартует автоматически после `uartmuxd`.

## CLI-команды `mcu`

| Команда | Что даёт |
|---|---|
| `mcu getver` | версия прошивки STM32 (`OK v6.8.0 ...`) |
| `mcu getvolt` | напряжение АКБ |
| `mcu getsys` | статус системы STM32 (источник питания и пр.) |
| `mcu getpcbrev` | ревизия платы |
| `mcu buttblock state` / `mcu buttblock time` | блокировка кнопок |
| `mcu reset` | перезапуск STM32 |
| `mcu setbright 0..7` | яркость LED |
| `mcu l <ch>=<цвет>,s<яркость>` | ручное управление LED-каналами (`2`=2.4G, `5`=5G, `zb`, `i`, `sh`, `a`) |

## Мониторинг батареи — пример

```sh
# разово:
mcu getvolt && mcu getsys

# ubus-подписка на события питания (переход на батарею, восстановление, ошибка БП):
ubus listen 'mcud.mcu.*'
#   mcud.mcu.pwroff  — пропало внешнее питание (работаем от АКБ)
#   mcud.mcu.pr      — питание вернулось
#   mcud.mcu.paerr   — ошибка/деградация БП
#   mcud.mcu.siren   — тревожный сигнал
#   mcud.mcu.lid / rst / log — прочие события
```

Скрипт-пример для cron (лог + реакция на переход на батарею):

```sh
#!/bin/sh
# /usr/bin/batt-watch — в cron: */5 * * * *
V=$(mcu getvolt 2>/dev/null | awk '{print $(NF)}')
S=$(mcu getsys 2>/dev/null)
logger -t batt "volt=$V sys=$S"
```

## Звук (siren)

В схеме устройства звуковой канал заведён на STM32: вендорный демон шлёт
событие `mcud.mcu.siren` через ubus, а сценарии тревоги активирует штатный
стек Perenio (датчики дымы/утечки → сирена). На «чистой» OpenWrt:

- пассивно: события сирены видны через `ubus listen` (если сирена запущена
  сценарием STM32);
- активно: команда ручного запуска сирены в вендорных скриптах **не
  встречается** — требуется эксперимент: сырые команды в `/dev/ttyS1`
  (как LED: `echo '#0siren 1' > /dev/ttyS1` — синтаксис не подтверждён) или
  через `mcu send ...` (клиент поддерживает `query/post/send`).

B1ackSn0w (4PDA #846) сообщил, что «звук» в его сборке работает —
уточнить синтаксис можно в ветке 4PDA.

## Зарядка/АКБ

Аппаратное управление зарядкой делает STM32 сам (хост не участвует) —
поэтому «зарядка» не требует софта: `mcu getvolt`/`getsys` показывают
состояние, события `pwroff`/`pr` сигнализируют о переключениях.
