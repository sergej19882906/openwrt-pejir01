# Расширение Telegram-бота PEJIR01 — дизайн

Дата: 2026-11-28
Статус: согласован с пользователем, готов к реализации
Релиз: `.77` (отдельно от `.76`, сборку `.76` не трогаем)

## 1. Задача

Мост Telegram (`pejir-tg`, патч 0110) умеет только пересылать входящие SMS
и принимать команды `/sms`, `/status`, `/reboot`, `/chatid`, `/help`.
Пользователь хочет расширить его:

- управление Wi-Fi (включение/выключение радио и отдельного SSID);
- управление LTE (смена APN, перезапуск LTE);
- управление светодиодами;
- диагностические команды `/signal`, `/uptime`, `/battery`;
- отправка файлов из роутера в чат;
- чтение веб-страниц (внешних и локальных).

Решения пользователя (опрос): Wi-Fi — вкл/выкл радио и SSID, LTE — APN и
перезапуск; опасные команды — только с защитным кодом; файлы — из `/tmp`
и `/www` до 20 МБ; веб — внешние и локальные адреса, без ограничения
длины; релиз — отдельный `.77`.

## 2. Ограничения и решения

| Вопрос | Решение |
|---|---|
| Где живёт код | Три маленьких helper'а вместо раздувания `pejir-tg` (см. §3) |
| Защита | Опасные команды требуют защитный код (`pejir_telegram.main.protect`), как сейчас у `/reboot` |
| Отправка файлов | `multipart/form-data` вручную: в образе `wget-ssl` (GNU wget), `curl` нет; тело собирается на диске и отправляется потоком |
| Размер файла | До 20 МБ (лимит Telegram 50 МБ), только `/tmp` и `/www` |
| Длина текста | Telegram режет до 4096 символов — присылаем первые ~4000 + многоточие. «Без ограничения» технически невозможно |
| Веб | `wget -qO-` + вырезание HTML-тегов; разрешены и внешние, и локальные адреса |
| Wi-Fi | `/etc/config/wireless` в образе отсутствует (конфиг приезжает из стоковой прошивки) — команды честно отвечают «Wi-Fi не настроен» |
| LTE | Смена `network.lte.apn` + перезапуск `/etc/init.d/47-pejir-lte`; ответ сразу, статус — через минуту |
| Конкуренция | `flock` (есть в образе) сериализует опасные операции |
| Выключение Wi-Fi | Интернет роутера идёт через LTE (`eth1`), поэтому бот продолжит работать; отвалится только телефон из LAN |

## 3. Пакет и файлы

```
package/pejir-telegram/root/usr/libexec/
  pejir-tg          # точка входа: разбор команды, защитный код, маршрутизация
  pejir-tg-send     # отправка сообщений и документов (multipart)
  pejir-sys         # системные команды: signal, uptime, battery, led, wifi, lte
```

Правило разделения: `pejir-tg` не растёт (остаётся разбор команды и
безопасность), `pejir-tg-send` знает только про Telegram, `pejir-sys` —
только про систему и ничего не знает про Telegram.

Светодиоды — через уже готовый `/usr/libexec/pejir-led` (`status`, `set`,
`auto`, `off`, `brightness`), своя логика индикаторов не дублируется.

### 3.1. `pejir-tg-send`

- `text <строка>` — обычное сообщение (`sendMessage`, обрезка до 4000);
- `file <путь>` — документ (`sendDocument`, multipart).

Multipart собирается так:

```
--BOUNDARY
Content-Disposition: form-data; name="chat_id"

<chat_id>
--BOUNDARY
Content-Disposition: form-data; name="caption"

<подпись>
--BOUNDARY
Content-Disposition: form-data; name="document"; filename="<имя>"

<содержимое файла>
--BOUNDARY--
```

Отправка: `wget --post-file=<тело> --header="Content-Type: multipart/form-data;
boundary=BOUNDARY" -qO- https://api.telegram.org/bot<token>/sendDocument`.
Тело готовится в `/tmp` (файл + заголовки), память не расходуется.

Проверки перед отправкой: путь существует; путь внутри `/tmp/` или `/www/`;
размер ≤ 20 МБ (`stat -c %s`); имя файла — без пути и кавычек.

### 3.2. `pejir-sys`

| Подкоманда | Источник данных |
|---|---|
| `signal` | `/tmp/pejir-modem.json` (rssi, csq_per, cops, mode) |
| `uptime` | `/proc/uptime`, `/proc/loadavg`, `/proc/meminfo` |
| `battery` | `/tmp/pejir-battery` (тот же разбор, что в `perenio-battery.js`) |
| `led ...` | `/usr/libexec/pejir-led` |
| `wifi ...` | `uci show wireless`, `uci set/commit`, `wifi reload` |
| `lte ...` | `uci get network.lte.apn`, `/etc/init.d/47-pejir-lte restart` |

Все команды возвращают текст и код 0/1 — вызывающий (`pejir-tg`) сам
решает, что отправить в чат.

### 3.3. Команды бота

Без защитного кода (только чтение):

- `/status` — сводка: версия, модем, LTE, uptime, сигнал, заряд;
- `/signal` — RSSI/CSQ, оператор, тип сети;
- `/uptime` — время работы, load average, память;
- `/battery` — уровень, напряжение, состояние зарядки;
- `/led status` — текущие индикаторы;
- `/led off`, `/led <имя> <цвет> [режим]`, `/led auto <имя> on|off`,
  `/led brightness <0-7>` — управление индикаторами (косметика, без кода);
- `/help`, `/chatid`.

С защитным кодом (код — последним словом команды):

- `/wifi status` — радио, SSID, состояние;
- `/wifi radio <имя> on|off` — включить/выключить радио (`radio0`, `radio1`);
- `/wifi ssid <имя> on|off` — включить/выключить отдельный SSID;
- `/wifi reload` — перезагрузить конфиг беспроводной связи;
- `/lte status` — интерфейс, APN, адрес, состояние PDP;
- `/lte apn <apn>` — сменить APN и перезапустить LTE;
- `/lte restart` — перезапустить LTE-интерфейс;
- `/file <путь>` — прислать файл (≤ 20 МБ, только `/tmp` и `/www`);
- `/web <url>` — прислать текст страницы;
- `/sms <номер> <текст>`, `/reboot` — как сейчас.

### 3.4. Правила безопасности

- Команды выполняются только из чата, указанного в `pejir_telegram.main.chat`.
- Для списка опасных команд (`wifi`, `lte`, `file`, `web`, `sms`, `reboot`)
  требуется защитный код; код передаётся последним словом и сверяется с
  `pejir_telegram.main.protect`. Если код не задан — команда отклоняется.
- Если защитный код не задан, опасные команды невозможно выполнить вовсе
  (это осознанное поведение: лучше не настроено, чем открыто).
- Как и сейчас, команды старше 10 минут не выполняются (после обесточивания
  Telegram отдаёт очередь разом).

## 4. Поток данных

```
Telegram ──getUpdates──▶ pejir-tg (цикл watch, раз в interval)
                            │ разбор команды
                            ├─ проверка чата и возраста команды
                            ├─ проверка защитного кода (для опасных)
                            ├─ flock /tmp/pejir-tg.lock (для опасных)
                            │
                            ├─▶ pejir-sys <подкоманда>  → текст
                            │      ├─ /tmp/pejir-modem.json, /proc/*, /tmp/pejir-battery
                            │      ├─ /usr/libexec/pejir-led
                            │      ├─ uci wireless + wifi reload
                            │      └─ uci network.lte + /etc/init.d/47-pejir-lte restart
                            │
                            └─▶ pejir-tg-send text|file   → Telegram
                                   ├─ sendMessage
                                   └─ sendDocument (multipart через wget)
```

Ответ на опасную команду с долгой операцией (перезапуск LTE) отправляется
сразу («перезапускаю»), фактическое состояние пользователь увидит в
следующем `/status` или `/lte status`.

## 5. Обработка ошибок

- Нет токена или chat ID → сообщение «не задан токен/чат», без падения;
- `wget` не вернул JSON или вернул `"ok":false` → в чат уходит текст
  ошибки Telegram (обрезанный до 200 символов), в журнал — полный ответ;
- файл не найден / слишком большой / не в `/tmp` и `/www` → понятный
  текст пользователю, отправка не выполняется;
- веб-страница не скачалась или пустая → сообщение об ошибке, без
  «пустого» ответа;
- `/etc/config/wireless` отсутствует → «Wi-Fi не настроен на этом устройстве»;
- LTE не поднялся после перезапуска → сообщение об этом + подсказка
  посмотреть `/lte status`.

## 6. Тестирование

Новый тест `tests/test-telegram-ext.sh` (обязан падать на старом коде и
проходить на новом):

1. в дереве есть `pejir-tg-send` и `pejir-sys`, оба исполняемые;
2. `pejir-tg` знает новые команды (`/signal`, `/uptime`, `/battery`,
   `/led`, `/wifi`, `/lte`, `/file`, `/web`) и требует защитный код для
   опасных;
3. лимиты файлов соблюдаются: только `/tmp` и `/www`, ≤ 20 МБ;
4. multipart собирается правильно (тест с подставленным `wget`, как в
   `tests/test-telegram.sh`);
5. `/web` вырезает HTML-теги и обрезает текст до 4000 символов;
6. `pejir-sys signal|battery|uptime` возвращает осмысленный текст на
   подставленных файлах (тестовые `/tmp/pejir-modem.json`,
   `/tmp/pejir-battery`).

Ручная проверка на устройстве: `check_rel77.sh` — новая секция с
проверкой наличия helper'ов, команд и лимитов.

## 7. Релиз

- Патч `0175` (фиксики серии — новым патчем поверх, номера не
  переиспользуются).
- Релиз `.77` — отдельный от `.76`; сборка `.76` не перезапускается.
- В `CONFIG_PACKAGE_*` новых пакетов не появляется — файлы добавляются в
  существующий `pejir-telegram` (пакет уже включён в образ).
- README и CHANGELOG обновляются под `.77`.

## 8. Что НЕ входит

- отправка файлов из произвольных путей (только `/tmp` и `/www`);
- команды, доступные из групп без защитного кода;
- управление Zigbee-модулем, VPN, multi-WAN;
- веб-страницы больше ~4000 символов (предел Telegram);
- голосовые сообщения и фото с камеры.
